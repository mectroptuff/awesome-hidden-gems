# Contributing Guidelines

Thanks for wanting to contribute! This list only works if it stays high-signal, so please read this before opening a pull request.

## What belongs on this list

- **You (or another contributor) have personally used the tool.** No submissions based on a tweet or a headline alone.
- **It's actively maintained.** Check for recent commits/releases. A project with no activity in over a year is generally not a good fit, unless it's simply "done" and stable by design.
- **It's genuinely underrated.** As a rule of thumb, prefer tools that most developers in the relevant space wouldn't already know about. There's no hard star-count cutoff — some tools grow fast — but a well-known, mainstream project (React, Docker, VS Code, etc.) is not what this list is for.
- **It's open source**, with a clear license.

## How to submit a tool

### Option A: Pull request (preferred)

1. Fork the repo and create a branch.
2. Add your entry to the relevant category, keeping the list alphabetically sorted within that category.
3. Use this exact format:

   ```markdown
   - [tool-name](https://github.com/org/repo) - One clear, concise sentence explaining what it does and why it's worth using. Ends with a period.
   ```

4. If no existing category fits, propose a new one, or open an issue first to discuss it.
5. Run a spell-check on your addition and make sure the link works.
6. Open the pull request. Explain in a sentence or two *why* you're recommending this tool — this helps reviewers and gets reused in the PR discussion.

### Option B: Open an issue

If you don't want to deal with Git, open an issue using the "Suggest a tool" template and fill in the requested details. A maintainer will turn it into a PR.

## Review process

- Every PR is checked automatically for formatting (`awesome-lint`) and link validity.
- A maintainer will review for fit (see "What belongs on this list" above). We may ask for a shorter/clearer description, or politely decline if the tool is too mainstream or unmaintained.
- Please be patient — this is a community-maintained list.

## Code of Conduct

Be respectful and constructive. No self-promotion spam, no low-effort mass PRs, no arguing about a decline decision.
